## 🚀 Featured Projects

<details>
<summary><b>🏨 Kubernetes Hotel Management System Cluster</b> — Production-Grade K8s Architecture</summary>

<br/>

**A fully architected 3-tier application deployed on a multi-node KinD cluster, demonstrating enterprise-level Kubernetes resource management, workload isolation, and persistent storage.**

| Attribute | Details |
|:---|:---|
| **Stack** | Kubernetes · KinD · NGINX Ingress · MySQL StatefulSet · YAML manifests |
| **Architecture** | 3-tier: Frontend / Backend / MySQL across 15 YAML manifests |
| **Security** | Kubernetes Secrets (secretKeyRef), namespace isolation, RBAC-ready |
| **Performance** | Resource governance via namespace-scoped LimitRange on all container tiers |
| **Persistence** | 10Gi PersistentVolume + PVC, auto-initialized via SQL ConfigMap |
| **Routing** | NGINX Ingress Controller: `/` → Frontend, `/api` → Backend |
| **Scheduling** | Node Taints, Tolerations, Node Affinity rules for workload pinning |
| **Repository** | [![GitHub](https://img.shields.io/badge/View%20Repo-181717?style=flat-square&logo=github)](https://github.com/zeyadbilal) |

**Key Engineering Decisions:**
- Isolated workloads across worker nodes using Node Taints and Affinity — Backend and MySQL pinned to dedicated node
- MySQL deployed as a **StatefulSet** (not a Deployment) to guarantee stable identity and persistent storage
- SQL schema auto-initialized at startup via ConfigMap mounted at `/docker-entrypoint-initdb.d`
- Credentials injected securely cluster-wide using `secretKeyRef` — zero plaintext config

</details>
